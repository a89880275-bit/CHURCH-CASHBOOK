# 장부 입력·거래내역 좌우 배치

2026-11-12 사용자 요청에 따라 화면 배치만 변경했다. 관리자/담당자 권한, 거래 저장·수정·삭제·이력, 이월/잔액 계산, 마감 검사, 인쇄·Excel·JSON API 및 데이터 저장 구조는 그대로다.

- 모든 테마에서 거래 입력은 왼쪽 상시 폼, 거래내역은 오른쪽이다. 수입 등록·지출 등록 버튼을 제거하고 폼의 거래 유형 선택을 사용한다. 기존 거래 선택/수정 버튼으로 왼쪽 폼에서 수정한다. 초기화용 작은 신규 입력 버튼과 취소·미저장 입력 보호를 유지한다.
- 조회 조건은 짧은 입력 폭을 사용해 조회 버튼까지 한 줄에 배치한다. 삭제 이력 포함과 초기화 도구는 거래내역 제목 쪽으로 옮겼다. 모바일에서는 조건을 여러 줄로 표시한다.
- 열 순서는 거래일/유형/계정/적요(비고)/수입금액/지출금액/거래 후 잔액/작업/작성자다. 작성자 아래 수정 시각과 버전은 보존한다. 거래 후 잔액은 기존 API 값을 모든 테마에 표시한다.
- 표 아래 기초잔액·수입금액·지출금액·잔액을 한 줄로 표시한다. 이때 ‘기초잔액’은 조회 시작 전 잔액(기존 기초잔액과 이전 거래 반영)이다. 등록한 최초 기초잔액은 왼쪽 원래 설정 안내에서 별도로 확인·관리한다. 수입/지출은 검색 결과, 잔액은 검색 필터 제외 부서 누적 기준을 유지하며 툴팁에 명시한다.
- 인쇄·Excel·JSON 백업은 작은 아이콘으로 표시하고 접근성 이름·툴팁을 제공한다.
- Modern Dark/Classic ERP Light의 기존 색상과 Pastel Diary Book의 표지·종이·링 장식을 유지한다. 다이어리 링 간격을 좌우 페이지 비율에 맞춰 입력·표를 가리지 않도록 조정했다. 900px 이하에서는 입력 위·내역 아래의 단일 열로 전환한다.

## 검증

- UI 기간·세 테마·열 순서·상시 입력·아이콘 도구 검사를 포함한 관련 테스트 34개 통과.
- 최종 TypeScript/Vite/Functions 빌드 및 빌드 파일 실제 비밀값 미포함 검사 통과. diff 공백 검사 통과.
- 외부 DB 없는 임시 JSON 검수 환경에서 세 테마 전환 중 입력값 유지, 신규 저장·재조회, 수정 사유 입력 후 수정 저장, 미저장 입력 보호를 확인했다.
- 1280px 및 1600px PC에서 검색줄이 조회 버튼까지 한 줄에 들어감을 확인했다. 390px 모바일에서 입력/내역 단일 열과 페이지 가로 넘침 없음, 브라우저 오류 없음도 확인했다.
- Neon DB·Auth0 설정·기존 사용자/회계자료는 변경하지 않았다. Netlify 배포는 실행하지 않았다.

변경 파일: src/ledger.tsx, src/ledger-workspace.css, tests/ledger-period-ui.test.tsx, docs/deployment-policy.md 및 이 문서.
