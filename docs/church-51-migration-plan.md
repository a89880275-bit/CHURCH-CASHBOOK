# 주내교회 51개 표준 과목 및 기본 템플릿 적용 계획 (테스트 DB 적용 완료)

2026-11-09 사용자의 명시 승인 후 아래 범위를 테스트 DB에 적용했습니다. 51개 등록·신규 부서 기본 템플릿 활성화를 완료했으며, 기존 부서 소급 변경은 하지 않았습니다. 상세 실행 결과는 구현 기록을 참조합니다. 아래는 승인 당시 계획입니다.

## 기존 자료와 변경 범위

지정된 Neon 테스트 DB를 읽기 전용으로 확인했습니다. 기존 SQL 테이블 5개 및 JSON 체크섬이 정상이며, 부서 계정 6개/거래 참조 3개/공통 마스터 미등록 상태입니다. 비공개 적용 전 사본을 보관했습니다.

SQL 테이블·열·권한은 변경하지 않습니다. 공통 원본에 선택적 isDefault/treatment/seedKey, control에 선택적 accountTemplate 설정만 추가합니다. 누락 필드에 기본값을 강제 삽입하지 않아 구자료의 직렬화/체크섬을 유지합니다.

승인 후 테스트 DB에 제공된 수입 19개·지출 32개 총 51개만 추가하고 신규 부서 기본 템플릿을 활성화합니다. 소분류는 목록에 별도 지정이 없어 초기값 ‘일반’으로 두며 관리자가 변경할 수 있습니다. 기존 이름/코드 충돌은 자동 병합하지 않고 중단합니다. 동일 seedKey로 다시 적용해도 원본을 중복 생성하거나 관리자 수정사항을 덮어쓰지 않습니다.

기존 부서에는 기본 과목을 소급 추가하지 않습니다. 기존 계정 ID/코드/이름/사용 상태, 거래/버전/해시/잔액/마감/권한/배정은 그대로 보존합니다. 기존 부서가 추가하려면 선택 가져오기를 사용하며 같은 이름의 기존 과목은 관리자 확인이 필요합니다.

신규 부서 생성은 기본 과목 복사·코드 발급·감사이력과 같은 트랜잭션으로 처리합니다. 초기 기본 항목은 11개이며 나머지 40개를 선택 등록합니다. 관리자가 기본 여부를 변경하면 이후 신규 부서에만 적용됩니다. 활성 기본 과목이 0개이면 활성화를 거부합니다. 현재 기본 수와 자동 등록 활성 상태를 관리자 화면에 표시합니다.

표준 코드와 부서 계정 코드는 서버가 발급합니다. 신규 코드 입력 화면은 없으며 기존 코드는 읽기 전용으로 표시합니다. 이전 API는 호환을 위해 유지하되 기본 업무 흐름은 공통 목록 선택입니다.

## 이월·환불 처리

전년이월은 목록상 수입 분류에 두되 OPENING_BALANCE로 지정합니다. 부서 계정으로 복사되더라도 일반 거래 API와 입력 선택에서 차단하며 기존 관리자 기초잔액 기능을 사용합니다. 자동으로 금액 0을 생성하거나 기존 잔액을 수정하지 않습니다. 기초잔액은 수입 실적에 포함하지 않고 잔액 계산에만 한 번 반영합니다.

환불금은 REFUND_REVIEW로 표시합니다. 원거래 확인 없이 일반 수입 거래로 등록하는 것을 차단하여 원거래 취소와의 중복을 방지합니다. 부분 환입/원거래 연결/중복 환급 상한 검증을 포함한 전용 환불 업무는 아직 구현하지 않았습니다. 전용 처리 전에 원거래 유형·기간·마감·환급 여부를 관리자와 확인해야 합니다.

기존 계정에 이름만 보고 이월/환불 처리를 자동 적용하지 않습니다. 특별 처리 원본과 기존 계정을 연결하려면 기존 거래 집계를 검토하는 별도 이전 계획이 필요하며 현재 연결 API에서 차단합니다. 과거 자료의 재분류/재집계는 본 승인 범위에 없습니다.

공통 원본 이름/상태/기본 여부 변경은 기존 부서 복사본과 거래를 자동 변경하지 않습니다. 수입/지출 및 회계 처리 방식은 생성 후 변경을 차단합니다.

## 적용 및 복구 순서

1. 최신 제어 JSON/체크섬/권한과 51개 등록 충돌을 재확인하고 사본을 보관합니다.
2. 관리자 변경 계획 미리보기의 목록·기본 11개·추가 개수·충돌·revision·checksum을 확인합니다.
3. 관리자 승인 체크, 사유, INSTALL_51 확인값을 받은 API에서 51개 추가와 템플릿 활성화를 한 번에 반영합니다. 중간 실패는 전체 롤백하며 결과 불명 시 다시 조회합니다.
4. 기존 계정·거래 참조와 잔액이 바뀌지 않았는지 확인합니다. 별도 검수용 신규 부서의 11개 및 선택 등록을 검수합니다.
5. 코드 롤백만으로 새 JSON 필드를 제거하지 않습니다. 문제 발생 시 자동 등록을 중지하고 새로 발생한 거래를 대조한 통제된 복구를 수행합니다. 기존 DB를 초기화하거나 과거 사본으로 무조건 덮어쓰지 않습니다.
