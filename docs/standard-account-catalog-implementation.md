# 공통 계정과목 구현 기록

## 최종 결과 및 테스트 배포

전체 21개 파일 / 268개 자동 테스트 통과, 타입 검사 및 Vite/Netlify 독립 함수 빌드 통과. 정적 파일 5개와 함수 ZIP 5개 항목의 실제 비밀값 미포함, 독립 번들 로드 검사 통과. 계정 전환 진단 보완 후 관련 30개 테스트도 재실행해 통과했다.

지정된 cool-scone-571b5f 테스트 사이트에 배포했다. 최종 배포 ID는 6af129b1197e2caa33cb3b2a이다. 운영 사이트/요금제/DB 스키마를 변경하지 않았고, 기존 비밀값은 공식 Functions 전용 배포 변수로 재전달했다. 배포 전후 비공개 제어 JSON 사본을 비교해 payload, revision, checksum이 모두 동일함을 확인했다. 기존 계정 6개/거래 참조 3개와 공통 마스터 미등록 상태도 유지했다.

배포 후 공개 앱/로그인 PKCE/실제 DB 세션 조회/비로그인 관리자 API 차단/공개 결과물 비밀값 미포함 검사를 통과했다. 실제 브라우저의 이전 Auth0 SSO 계정은 회계프로그램의 활성 사용자로 인정되지 않아 PRINCIPAL/UNAUTHENTICATED 단계에서 차단되었다. 이메일이나 Google 계정을 자동 연결하지 않았다. 오류는 비밀값/식별자 없는 단계 코드만 기록하도록 보완했다.

사용자가 Auth0 로그아웃 복귀 주소 저장 완료를 확인했다. 배포된 ‘다른 계정으로 로그인’에서 실제 Auth0 로그아웃 확인 → 서버 callback 상태 검증 → 새 인증 화면 진입을 확인했으며, 일반 로그인 URL로 다시 들어가도 기존 SSO 자동 복귀 없이 새 인증 화면을 제공했다. 실제 관리자 자격증명 입력과 공통 원본의 실제 등록은 사용자에게 남겨 두었다. 등록/가져오기 자체의 기능 검수는 독립 저장소/브라우저 fixture에서 수행했다.

## 구현 범위

- 관리자 전용 /standard-accounts 화면 및 원본 등록/수정/중지 API. 유형·대/소분류·과목명·표준 코드·정렬·버전 관리, 감사이력 검색 지원.
- 부서 계정 화면의 ‘공통 과목 선택’: 이름/코드/분류 검색, 수입·지출 및 대/소분류 필터, 다중 선택, 검색 결과 선택, 최대 100개 확인 후 가져오기.
- 서버에서 현재 배정 부서와 활성 상태를 재검사하고, 기존 control 행 잠금/revision 트랜잭션에서 코드 발급·중복 검사·계정 생성·감사 기록을 함께 처리한다. 불명확한 저장 결과를 자동 재시도하지 않고 같은 requestId의 완료 기록을 재조회할 수 있다.
- 이미 가져온 원본은 ‘사용 중’ 또는 ‘등록됨·사용 중지’로 표시하고 중복 체크를 막는다. 중지된 부서 계정은 기존 수정 화면에서 재활성화한다.
- 기존 수동 계정과 같은 이름/유형이면 자동 등록·매칭하지 않고 검토 상태로 표시한다. 관리자는 기존 코드/이름과 원본을 확인하고 사유를 입력한 뒤 출처만 연결할 수 있다. 기존 ID/코드/거래는 유지한다.
- 기존 직접 등록·수정·중지 유지. 일반 계정 수정이 가져오기 메타데이터를 지우지 않도록 수정했다. 부서 목록에도 분류를 표시하며 원본이 없는 복원 자료에는 ‘원본 확인 필요’를 표시한다.
- 공통 원본 수정/중지는 기존 부서 복사본에 자동 전파하지 않는다. 기존 거래, 통계, 계정 사용 이력 및 마감은 부서 계정 ID를 계속 사용한다.
- 공통 목록 관리자 JSON 백업/검증·미리보기/복원. 복원 전 사본을 보관하며 부서 계정/거래/권한은 교체하지 않는다. 백업에 없는 원본은 물리 삭제하지 않고 중지한다. 다른 환경 작성자가 없는 원본 백업은 자동 권한 연결 없이 거부한다.
- 기존 금융 v1 백업 읽기 유지. 가져오기 정보가 포함된 신규 금융 백업은 v2로 표시하며 부서 복원 시 현재 공통 원본이 없어도 독립 계정·거래를 유지한다. 공통 원본 복원은 별도 관리자 경로다.
- PC 모달과 모바일 카드형 선택 목록, 단일 스크롤 및 고정 하단 동작 버튼. Modern Dark, Classic ERP Light, Pastel Diary Book 스타일 유지.

## DB 사전 점검 및 보존

지정된 테스트 사이트 및 Neon 브랜치만 대상으로 읽기 전용 트랜잭션에서 실제 cashbook 테이블을 확인했다. control/transactions/snapshots/sessions/backups 존재와 기존 JSON 파싱·체크섬 일치를 확인했으며 비공개 로컬 사본을 보관했다. 당시 기존 부서 계정 6개, 거래 참조 3개, 공통 마스터 없음이었다. 접속정보/실제 계정명/거래 내용은 출력하지 않았다.

새 SQL 테이블·열·권한을 추가하지 않았다. control의 standardAccounts/accountImports 및 부서 계정의 출처 필드는 선택적으로 추가하며, 구자료에 새 기본값을 끼워 넣지 않아 기존 직렬화/체크섬을 보존한다. 기존 부서 계정을 자동 연결하거나 거래를 재작성하는 마이그레이션을 실행하지 않았다. 테스트 브라우저의 예시 과목은 독립 메모리 fixture에만 있으며 실제 DB에 초기 표준 목록을 넣지 않았다.

## 검수

전체 자동 검수에는 기존 로그인/권한/장부/통계/마감/백업과 신규 공통 과목 테스트가 포함된다. 신규 API 테스트는 임시 실제 JSON 파일 저장소를 사용하고, 독립 PostgreSQL 풀의 동시 가져오기·코드 중복 방지·기존 거래 참조 보존을 실제 격리 PostgreSQL 엔진에서 검증한다.

동시 저장 테스트는 특정 요청이 반드시 먼저 끝난다고 가정하지 않고 실제 성공한 요청 ID의 재조회 동작을 확인한다. 원본 중복/유형 변경, 비관리자 쓰기, 타 부서 접근, 일괄 오류의 전체 미반영, 자동 코드 충돌 건너뛰기, 기존 수동 과목 연결, 원본 중지 후 과거 금액 보존, 백업 v1/v2 및 원본 미존재 복원도 검수한다.

실제 브라우저에서는 DB 연결 없는 127.0.0.1:5180 메모리 fixture로 담당자 다중 가져오기, I000001/E000001 발급, 가져온 항목의 체크 비활성화, 세 테마 및 390px 모바일 카드 표시를 확인했다. 화면의 ‘검수용’ 과목은 교회 공식 표준이 아니다.

실행: `pnpm exec vitest run --reporter=dot`, `pnpm run build`, `node scripts/check-invitation-build.mjs`, `node scripts/check-function-bundle.mjs`.

## 남은 범위

교회에서 확정한 전체 표준 과목 목록은 아직 제공/확정되지 않았다. 관리자가 화면에서 등록할 수 있으며 임의 예시를 공식 목록으로 자동 등록하지 않는다. 신규 과목 추가 요청/승인함은 승인된 설계의 2단계로 남긴다. 운영 적용은 별도 검수 대상이다.

같은 작업 트리에 이전 승인된 계정 전환 기능이 포함되어 있다. 사용자가 필요한 Auth0 Allowed Logout URLs 등록 완료를 확인했으므로 두 기능의 검증된 번들을 테스트 사이트에 함께 배포할 수 있다. 실제 Auth0 SSO 양방향 전환 검수는 자동 테스트/독립 로컬 검수와 구분해 기록한다.
