# Netlify 배포 준비 점검

후속 구현: 같은 날 사용자 승인으로 PostgreSQL + JSON 어댑터를 추가했습니다. 실제 엔진 기반 통합 검증과 초기 관리자 설정 도구를 구현했습니다. [최신 결과·설정 절차](postgres-deployment.md)를 우선 참조하세요. 아래 표는 어댑터 구현 전 점검 기록입니다. 실제 OIDC/관리형 DB/Netlify 연결 검수는 여전히 미완료입니다.

점검일: 2026-11-07. 현재 작업 사본 기준이며 실제 Netlify 사이트에 접속하거나 배포하지 않았습니다.

## 판정

정적 화면 빌드는 가능하지만 실제 다중 사용자 회계 운영은 준비되지 않았습니다. 인증 제공자 연결, 원격 초기 자료 준비, 검증된 원격 쓰기 구조 및 실환경 검수가 필요합니다. 로컬 파일 저장소 테스트 결과를 Netlify Blobs의 동시성 보장으로 확대하지 않습니다.

| 항목 | 상태 | 근거/제한 |
| --- | --- | --- |
| React 화면·3개 테마·반응형 | 구현 | 기존 UI 유지, 이번 점검에서 브라우저 전 화면 재검수는 하지 않음 |
| 사용자·부서·배정·독립 계정코드 | 로컬 완료 | 운영 Blobs 변경은 차단 |
| 장부 등록·수정·삭제·검색·이월/잔액 | 로컬 완료 | 실제 원격 저장은 미완료 |
| 월별·계정별·연간·통합 대시보드 | 구현 | 권한·집계 테스트 통과, 원격 데이터 연결은 미검수 |
| 월/연 마감·해제, 인수인계 | 로컬 완료 | 마감/해제 사유·감사기록, 최신 권한 검사. 운영 쓰기 미완료 |
| JSON 백업·검증·미리보기·복원 | 로컬 완료 | 3MB 한도. 인증 설정·현재 배정을 복원하는 전체 시스템 백업은 아님 |
| Excel·감사 검색·입력 이동 보호 | 구현 | 기존 테스트 및 이전 격리 브라우저 검수 기록 있음 |
| 사용자별 테마 영구 저장 | 로컬 완료 | 원격 쓰기 차단 상태에서는 해당 화면에만 적용 |
| 운영 OIDC 로그인 | 부분 구현 | PKCE/state/nonce·세션 코드 존재, 제공자/사용자 sub 연결 및 실제 로그인 검수 필요 |
| 관리자·부서 API 권한 | 구현 | 활성 상태·현재 배정 재검사, 로컬 인증 운영 차단 테스트 통과 |
| 원격 JSON 읽기 | 부분 구현 | 제어 JSON·거래 해시 검증 코드 존재, 실제 저장소 초기화/연결 미검수 |
| 원격 JSON 쓰기·동시 저장·복원 | 미완료 | BlobsRepository.writable=false, WRITE_NOT_VERIFIED. 환경변수만으로 해제 불가 |
| Netlify 설정 | 파일 준비 | dist 게시, Functions esbuild, API/SPA 리다이렉트, 보안 헤더, Node 24 설정 존재 |
| 실제 Netlify 빌드·배포·재배포 지속성 | 미검증 | 로컬 빌드 성공은 Netlify 배포 성공 증명이 아님 |
| 최신 코드 Git 반영 | 미완료 | 변경/신규 파일 다수 미커밋. 현재 HEAD 297f6bb |

## 이번 실행 결과

- Vitest: 14개 파일, 193개 테스트 통과.
- TypeScript: tsc --noEmit 통과.
- Vite: 프로덕션 빌드 통과.
- check-dist.mjs: 정적 결과물 JSON/source map/알려진 서버 설정 표식 검사 통과. 일반적인 비밀값 전체 탐지 도구는 아님.
- check-production.mjs: 종료 코드 1. 현재 프로세스의 APP_ORIGIN, OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET, COOKIE_KEY, BLOBS_STORE 미설정/부적합. 실제 Netlify 관리 화면의 설정 여부를 확인한 결과는 아님.

## 배포 전 처리 순서

1. 원격 회계 쓰기의 직렬화/트랜잭션 전략을 결정하고 구현·장애/경쟁 테스트를 수행합니다. 로컬 파일 잠금을 서버리스 여러 인스턴스에 그대로 적용하지 않습니다.
2. OIDC 제공자 웹 앱, HTTPS callback, 서버 전용 환경변수, 최초 관리자와 실제 sub 매핑, 원격 초기 제어 JSON 및 기존 자료 이전 절차를 준비합니다. 임시 로그인이나 공개 JSON으로 우회하지 않습니다.
3. 변경 코드를 검토해 커밋·푸시하고, 별도 테스트 Netlify 사이트/별도 저장소/테스트 사용자로 배포합니다. 현재 API는 운영 자료 공유를 막기 위해 deploy preview/branch context를 거절하므로 별도 테스트 사이트의 production context를 사용합니다.
4. 실제 로그인·로그아웃·세션 만료·중지 계정·부서 권한 회수·동시 저장·저장 실패·월/연 마감 경쟁·백업 복원·재배포 후 자료 유지·모든 테마 다운로드/입력 보호를 검수합니다.
5. 검수 통과 후 운영 자료를 이전하고 운영 배포합니다. 파일 백업의 별도 보관/복구 절차도 확정합니다.

OIDC는 최종 사용자 신원 확인용이며 Netlify 배포 자체의 필수 조건은 아닙니다. 현재 운영 인증 코드가 이미 OIDC이므로 설정을 연결하는 작업입니다. 자세한 절차는 [인증 안내](production-auth.md), 로컬 구현/제한은 [운영 기능 보고](stage4-operations.md)를 참조하세요.
