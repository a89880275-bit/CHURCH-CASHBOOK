# 실제 관리자 로그인과 원격 쓰기 검수

사용자가 Auth0 관리자 로그인을 완료했다고 확인한 후, 지정된 Neon 테스트 DB에서 승인된 subject에 해당하는 유효한 세션 및 ADMIN/ACTIVE 권한을 읽기 전용으로 확인했습니다. 세션 토큰/해시를 출력하거나 복사하지 않았습니다. 로그인은 기존 OIDC 토큰 교환·검증을 거쳤으며 이메일로 권한을 부여하거나 임시 인증을 발급하지 않았습니다.

## 원격 검증

`scripts/verify-neon-writes.ts`는 지정 프로젝트/브랜치/초기 관리자 상태와 기존 읽기 전용 플래그를 확인합니다. 새로 생성한 무작위 `cashbook_verify_*` 스키마에만 기존 저장소 SQL을 연결합니다. 운영/테스트용 실제 `cashbook` 테이블과 실제 세션에는 쓰지 않습니다. 검증용 세션이나 Auth0 사용자는 만들지 않습니다.

실제 Neon에서 다음이 통과했습니다.

1. 독립된 pooled 연결 2개를 통해 동시 등록 12건: 거래/감사 각 12건, revision 13, 수입 합계 78 일치.
2. 같은 revision의 동시 설정 변경: 하나만 성공하고 하나는 VERSION_CONFLICT.
3. 거래 객체 삽입 후 의도적 예외: 원본 객체와 제어 JSON이 모두 롤백됨.
4. JSON 백업 검증·미리보기·복원: 13건에서 백업의 12건으로 복원되고, 복원 전 별도 커밋 사본에는 13건이 보존됨.
5. 실제 테스트 DB의 관리자/부서/배정/회계 제어 JSON이 검증 전과 정확히 일치함.

새로 만든 임시 스키마만 제거했고 정상 완료를 확인했습니다. 해당 스크립트는 생성한 무작위 이름을 제한하며 기존 이름이 있으면 시작하지 않습니다. 실제 로그인·권한 검증과 분리된 저장소/백업 코드 검증입니다. 테스트 사이트의 공개 API에서 관리자·담당자 전체 업무 흐름을 모두 검수했다고 표시하지 않습니다.

## 테스트 사이트 입력 활성화

위 검증 기록을 확인한 뒤, 정확한 Netlify 테스트 사이트 `cool-scone-571b5f`의 ACCOUNTING_WRITES_ENABLED 값 하나만 true로 변경하고 재배포했습니다. 운영 사이트나 요금제는 변경하지 않았습니다. 비밀값 3개는 이전과 같이 해당 배포의 Functions 전용 `--secret-env` 방식입니다. 비밀값이 일반 범위 또는 VITE_*에 들어가지 않았는지 배포 전 검사했습니다.

배포 ID: `6aee91ca2a44893f0b55b1c9`.

TypeScript/프런트엔드/함수 Netlify 빌드 및 배포 성공. 실제 배포의 Auth0 요청·쿠키 키 검증·DB 세션 조회·잘못된 callback/익명 관리자 접근 차단·정적 응답 비밀값 미포함 검사가 다시 통과했습니다. UI의 기존 조회 전용 문구는 me.writable 상태에 맞게 표시하도록 수정했습니다.

## 현재 범위와 다음 검수

현재 테스트 사이트에서 입력이 가능합니다. 실제 화면에서 첫 테스트 부서를 저장·재조회하고, 부서별 계정·장부·마감·복원과 담당자별 접근 제한을 순서대로 검수해야 합니다. 실제 운영 회계자료를 옮기거나 운영 사이트에 배포한 상태는 아닙니다.

다음 사용자 작업은 부서·담당자 관리에서 테스트 부서 1개를 등록하는 것입니다. 원격 저장 검증 기록과 설정 변경 기록은 `.private/deployment`에 보관합니다.
