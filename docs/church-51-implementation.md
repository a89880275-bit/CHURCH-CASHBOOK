# 51개 계정과목 및 기본 11개 템플릿 구현 기록

## 실제 적용 상태

2026-11-09 사용자의 명시 승인 후 [적용 계획](church-51-migration-plan.md)에 따라 지정된 테스트 DB에 공통 51개(수입 19/지출 32), 기본 11개/선택 40개를 등록하고 신규 부서 기본 템플릿을 활성화했다. 테스트 사이트 cool-scone-571b5f에 호환 코드를 먼저 배포한 뒤 적용했다. 배포 ID는 6af133e4e6e23fd2cffc64c2, 적용 후 revision은 43이다. 운영 사이트·운영 DB 및 SQL DDL/권한은 변경하지 않았다.

적용 직전 최신 제어 JSON과 참조 거래를 비공개 파일로 백업하고 읽어 체크섬을 재검증했다. 기존 계정 6개·거래 참조 3개·거래 원문 및 공통 원본/템플릿/감사/리비전을 제외한 모든 제어 자료가 그대로 유지됨을 해시 비교로 검증했다. 감사이력은 기존 항목을 보존하고 설치 기록 1개만 추가했다. 실제 DB를 다시 읽은 설정으로 복제본에 신규 부서 기본 과목을 생성하여 11개를 확인했다. 검수용 부서나 계정은 실제 DB에 남기지 않았다. 관리자 화면의 실제 신규 부서 생성 확인은 사용자 확인 단계로 남긴다.

적용 당일 관련 테스트 43개(템플릿 12/공통 목록 13/PostgreSQL 18)가 정리 단계까지 통과했다. 표준 빌드는 Windows 샌드박스 상위 경로 접근 제한으로 처음 실패했으나 승인된 권한 확장 실행에서 변경 없이 통과했다. 타입 검사, 클라이언트·서버 번들, Netlify 함수 패키징 및 정적 파일/함수 아카이브의 실제 비밀정보 미포함 검사를 통과했다. 함수 전용 배포 비밀변수를 유지했다. 앞서 미실행으로 남긴 독립 번들 로드 검사 1건은 이번 실행에서도 재시도하지 않았다.

배포 후 실제 사이트의 HTML/자산, Auth0 인증 요청과 PKCE, 함수의 쿠키 암호화키 읽기, 실제 DB 세션 조회, 알 수 없는 세션/미인증 관리자 접근/잘못된 콜백 차단, 공개 응답의 실제 비밀정보 미포함 검사가 통과했다. 이 검사는 로그인 세션을 생성하지 않으므로 새 배포에서 실제 사용자 로그인과 신규 부서 화면 저장까지 완료했다고 주장하지 않는다.

## 구현

- 제공된 정확한 51개 목록(수입 19/지출 32), 초기 기본 11/선택 40을 고정된 seedKey로 구성했다.
- 관리자용 읽기 전용 변경 계획 미리보기와 revision/checksum/명시적 확인값/사유를 검사하는 적용 API를 추가했다. 등록 충돌 시 기존 과목을 자동 연결·덮어쓰기하지 않는다.
- 신규 부서 생성 트랜잭션 안에서 현재 활성 기본 과목을 부서별 독립 계정으로 복사하고 자동 코드를 발급한다. 부서 수정이나 기존 부서에는 소급 추가하지 않는다.
- 관리자 기본 포함 여부 및 자동 등록 활성/중지 설정을 제공한다. 기본 항목을 바꾸면 이후 신규 부서에만 반영된다.
- 수입·지출 선택 탭, 기존 검색·분류·다중 선택, 사용 중 표시와 중복 방지를 유지한다. 기본 항목 표시 및 이월/환불 처리 안내를 추가했다.
- 표준 코드도 서버 자동 발급을 지원한다. 신규 직접 코드 입력 버튼을 제거하고 기존 계정 코드는 읽기 전용으로 표시한다. 기존 API는 호환성 목적으로 남긴다. 부서 코드 입력 기능은 별개로 유지한다.
- 전년이월 계정은 기초잔액 전용이다. 일반 거래 등록을 API에서 거부하고 입력 선택에서도 제외한다. 기존 관리자 기초잔액 기능을 사용하며 수입 실적에 더하지 않는다.
- 환불금은 원거래 검토용으로 표시하고 일반 수입 거래 등록을 차단한다. 전용 부분 환입/원거래 연결/환급 상한 검증 자동화는 아직 미구현이다. 기존 거래를 취소하고 다시 환불금 수입을 올리는 중복 처리를 자동 허용하지 않는다.
- 기존 계정은 이름만으로 특수 처리로 바꾸지 않는다. 이월/환불 원본에 기존 계정을 연결하는 것도 별도 이전 검토가 필요하므로 차단한다.
- 공통 마스터 처리 방식과 수입/지출 유형은 변경 불가다. 이름·분류·기본 여부 변경을 과거 부서 복사본에 자동 전파하지 않는다.
- 템플릿 메타데이터가 있는 공통 목록 백업은 catalog-v2로 표시하며 기존 v1도 읽는다. 금융 백업 v1/v2 호환은 유지한다. 기본 플래그는 원본과 함께 복원되며 자동 등록 활성 상태는 현재 설정을 유지한다.

## 검증 결과와 한계

- 전체 기능 테스트 280개 통과. 마지막 전체 실행에서는 테스트 본문이 모두 통과했지만 Windows의 임시 PostgreSQL 폴더 EBUSY 때문에 정리 단계 종료가 실패했다.
- 테스트 fixture가 이미 검증한 단일 OS 임시 경로에 한해서만 삭제 재시도를 하도록 보완했다. 이후 권한 확장 없는 공식 Vitest configLoader runner로 PostgreSQL 테스트 18개를 재실행해 정리까지 통과했다.
- 동일한 샌드박스에서 공통 과목/51개 템플릿 테스트 25개 재실행 통과. TypeScript 검사 및 최종 Vite/서버 번들 빌드 통과. 빌드 결과 5개 파일의 실제 비밀값 미포함 검사와 git diff --check도 통과했다.
- 이월 1,200원 + 실제 수입 100원 검수에서 수입 실적 100원, 이월 1,200원, 잔액 1,300원을 확인했다. 이월/환불의 일반 거래 등록 거부, 관리자 권한, 동시 등록, 중복, 기존 부서 보존, 신규 기본 11개, 선택 가능 40개, 관리자 기본 변경 후 다음 부서에만 적용되는 것을 검증했다.
- DB 연결이 없는 메모리 브라우저 fixture에서 51개 미리보기/명시적 적용, 기본 11개 상태, 신규 부서 생성 및 선택창의 기본 항목 11개 체크 비활성화를 확인했다. 이 적용은 실제 Neon DB 적용이 아니다.
- 추가 독립 번들 로드 검사 1건은 자동 승인 검토의 사용량 제한으로 실행되지 않았다. 안전성 거절이 아니라 승인 검토 실패이며 해당 검사를 우회하지 않았다. 기존 단계에서 동일 검사 통과 이력은 있으나 이번 변경의 통과 결과로 대체하지 않는다.
