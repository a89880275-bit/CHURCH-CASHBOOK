# 담당자 직접 등록 제한 및 공통 선택창 밀도 개선

2026-11-09 요청 반영.

## 권한

- `/api/accounts` POST는 관리자만 허용한다. 요청 시점과 저장 트랜잭션 내부에서 현재 역할을 다시 확인한다.
- 담당자는 기존 계정의 코드를 PATCH로 바꿀 수 없다. 이름·정렬·사용 상태 관리 및 공통 목록 선택 가져오기, 부서별 접근 제한은 유지한다.
- 직접 등록 버튼은 이미 제거되어 있으며, 비어 있는 목록 안내도 공통 선택을 가리키도록 수정했다. 관리자 호환 API는 유지한다.
- DB 스키마·기존 계정·거래·권한 데이터는 수정하지 않는다.

## 선택창

- 선택창에서 중복 수입·지출 드롭다운을 없애고 전체/수입/지출 탭을 유지한다.
- PC 검색 입력 폭 160px, 대·소분류 각각 120px로 압축해 한 줄로 배치한다.
- 선택창의 표 셀 여백과 코드 보조 표시를 줄이고, 목록이 남은 높이를 사용하도록 구성했다. 다른 업무 표는 변경하지 않는다.
- PC 1440×900 검수에서 일반 행 30px/기본 표시 행 31px를 확인했다. 모바일 390×844에서는 카드형 3줄 구조로 약 78px이며 가로 넘침이 없다.
- 메모리 전용 검수 환경에서 51개 표시, 검색 결과 1개 필터링, 체크 선택 후 다음 버튼 활성화를 확인했다. 이 UI 검수는 실제 DB 자료를 변경하지 않는다.

## 검증

- 전체 테스트 282개 중 280개가 일반 샌드박스에서 통과했다. 두 다중 프로세스 검사는 Windows 사용자 조회 제한 때문에 실패했으며, 해당 두 파일을 승인된 권한 확장으로 재실행하여 58개 모두 통과했다.
- 직접 등록 차단, 코드 변경 차단과 무변경 보장, 저장 직전 관리자 권한 해제, 기존 담당자 수정·중지, 공통 선택 가져오기·자동 기본 등록 테스트를 포함한다.
- 최종 타입 검사·클라이언트/서버 빌드·함수 패키징·정적 파일과 함수 아카이브 비밀정보 검사 통과. 테스트 사이트 배포 ID: 6af13669c48c047eca3cafd6.
- 배포 후 HTML/자산, Auth0 PKCE 요청, 함수의 실제 DB 세션 조회, 미인증 관리자 접근 및 잘못된 콜백 차단, 공개 파일 비밀정보 미포함 검사가 통과했다. 실제 사용자의 새 로그인과 담당자 UI 전체 저장 과정을 자동 검사했다고 주장하지 않는다.
