# 명시적 로그아웃 및 계정 전환 구현 계획

소스 점검에 따른 계획이다. 이 단계에서 인증 코드, 세션, DB, Auth0 설정, 배포는 변경하지 않았다.

## 현재 상태

- POST /api/auth/logout은 현재 앱 세션을 저장소에서 삭제하고 HttpOnly 쿠키를 만료시킨다. Auth0 SSO는 종료하지 않는다.
- 일반 로그인에는 재인증 요청이 없으므로 남아 있는 Auth0 SSO에 의해 같은 계정으로 돌아올 수 있다.
- App은 focus 및 session-expired 이벤트에서 /me를 갱신한다. ThemeProvider만 사용자 ID로 key를 지정하며 업무 화면 전체에 사용자/세션 경계를 적용하지 않는다. 부서 선택값도 계정 변경 시 항상 초기화하지는 않는다.
- 회계 데이터는 각 화면의 React state에 보관한다. src/public에서 localStorage, sessionStorage, IndexedDB, Cache Storage, Service Worker에 회계 데이터를 저장하는 코드는 검색되지 않았다. API에는 no-store 응답 정책이 있다.
- 일부 화면은 취소 플래그/요청 번호로 오래된 응답을 무시하지만 공통 AbortController와 세션 세대 검사는 없다. 다중 탭 계정 변경 통지도 없다.
- 기존 장부 입력 보호를 재사용할 수 있다. 초대/관리자 등 입력 폼의 보호 범위는 별도 점검한다.

## 목표 동작

상단 사용자 메뉴에 ‘로그아웃’과 ‘다른 계정으로 로그인’을 제공하고 기존 로그아웃 아이콘도 유지한다. 세 테마의 업무 기능과 API 권한 검사를 보존한다.

로그아웃: 입력 저장/버림/취소 확인 → 앱 세션 폐기 확인 → 메모리 상태 정리 → Auth0 로그아웃 → 고정된 로그아웃 완료 화면. 자동 재로그인을 시작하지 않는다. 로컬 세션 삭제 실패 시 성공으로 표시하지 않고 재시도 안내를 한다. Auth0 로그아웃 실패와 앱 로그아웃 성공을 구분한다.

계정 전환: 동일한 입력 보호와 로그아웃 정리를 거친 뒤 Universal Login에 prompt=login을 전달해 기존 Auth0 SSO를 이용한 자동 복귀를 피한다. 기존 기본 로그인 흐름은 유지한다. 새 PKCE/state/nonce를 생성하고 callback에서 기존 sub 기반 권한을 다시 확인한다. 이메일 자동 연결 및 역할 변경은 하지 않는다. 추후 Google 등 외부 제공자가 추가되면 상위 제공자의 계정 선택 동작은 별도 검증한다.

같은 브라우저 프로필의 쿠키는 여러 탭에서 공유되므로 계정 전환은 그 프로필의 다른 탭에도 적용된다. 동일 프로필에서 관리자/담당자 동시 독립 로그인은 제공하지 않는다. 별도 브라우저 프로필은 계속 사용할 수 있다.

## 서버 계획

- 기존 POST 로그아웃을 확장해 현재 세션과 OIDC 진행 쿠키를 정리한다. GET 요청으로 앱 세션을 변경하지 않는다. Origin 검사를 유지한다.
- OIDC discovery의 end_session_endpoint를 이용한 Auth0 RP-Initiated Logout을 우선 검증한다. 현재 세션에는 ID token을 저장하지 않으므로 임의 id_token_hint를 만들지 않는다. 지원되는 client_id 방식과 제공자 확인 화면을 검증하고 필요하면 서버 전용 logout_hint 설계를 별도로 판단한다.
- 복귀 주소는 APP_ORIGIN 아래 고정 경로 /signed-out으로 제한한다. 임의 returnTo/외부 URL은 받지 않는다. 계정 전환 목적은 단기 무작위 state/서버 검증 쿠키로 묶으며 단순 URL 파라미터만으로 자동 로그인을 시작하지 않는다.
- Auth0 Allowed Logout URLs에는 정확한 테스트 복귀 주소가 필요하다. 기존 로그인용 앱에서 추가하며 Management API 앱을 변경하지 않는다. 설정은 구현 후 사용자에게 한 번에 하나씩 안내한다.
- 공통 요청에 인증된 현재 사용자/세션과 비교할 세션 컨텍스트를 도입한다. 이는 인증 수단이 아니라 오래된 탭이 새 계정의 쿠키로 저장 요청을 보내는 것을 막기 위한 추가 검사다. 업무 쓰기 및 로그아웃에 적용하고 서버 권한 검사는 계속 수행한다. 기존 세션 호환/교체 정책을 테스트한다.

## 화면 상태 정리

- 사용자/세션이 바뀌면 업무 트리 전체를 새로 마운트하고 현재 부서, 목록/통계/합계, 검색·페이지, 선택 거래, 초안, 감사 이력, 백업 미리보기, 파일 입력, 알림을 초기화한다. 새 계정의 서버 테마를 적용하며 서버의 테마 설정은 삭제하지 않는다.
- 공통 API 클라이언트에서 진행 중인 요청을 취소하고 이전 세션 세대의 늦은 응답/오류를 버린다. /me 갱신 경쟁도 같은 규칙으로 처리한다. 응답을 숨기는 것과 이미 서버에 반영된 저장을 취소하는 것은 다르므로 완료된 저장을 되돌린다고 설명하지 않는다.
- 앱이 만든 다운로드 Object URL 및 임시 DOM만 정리한다. 이미 사용자가 내려받은 파일, 다른 서비스 쿠키, 브라우저 전체 저장소는 지우지 않는다.
- BroadcastChannel(필요 시 민감정보 없는 storage 이벤트 대체)로 로그아웃/전환을 다른 탭에 통지한다. 다른 탭은 계정 자료를 즉시 숨기고 상태를 정리한 뒤 세션을 재확인한다. 알림에는 사용자 정보, 거래, 인증 토큰을 넣지 않는다. 다른 탭에서 자동 저장하지 않는다.
- pageshow/BFCache 및 뒤로가기·탭 복귀에서 세션 재검증 전에는 과거 업무 화면을 표시하지 않도록 처리한다. 브라우저 기록 자체의 완전 삭제를 보장하지 않는다.

## 검증과 적용 순서

1. 세션 컨텍스트/로그아웃/전환 모드 및 고정 복귀 경로 구현, 서버 테스트.
2. 업무 트리 초기화, 공통 요청 취소/세대 경계, 다중 탭 통지, 입력 보호 구현, UI 테스트.
3. 전체 기존 테스트 및 Netlify 빌드/번들 비밀값 검사.
4. 사용자에게 테스트 로그인 앱의 Allowed Logout URLs 설정 하나만 안내.
5. 테스트 사이트에만 배포하고 실제 Auth0 로그인 전환을 검수. 운영 적용은 별도다.

필수 검수: 관리자→담당자와 역방향, 같은 사용자 재로그인, 로그아웃 쿠키 재사용 차단, 잘못된 Origin/복귀 주소/전환 state 거부, 저장 실패/로그아웃 실패, 네트워크 지연 응답, 이전 탭에서 새 계정 쿠키로 쓰기 시도, 다중 탭·뒤로가기·BFCache, 미저장 입력 저장/버림/취소, 세 테마, 계정 중지/부서 변경 회귀 검증. 기존 237개 테스트는 이전 기능의 결과이며 이 신규 계획을 검증한 결과가 아니다.

## 외부 서비스 범위와 근거

기존 Auth0 + Netlify Functions를 재사용하며 별도 Management API 권한/비밀번호 저장/Netlify 유료 기능을 요구하지 않는 방향이다. Auth0 로그아웃이 Google 등 상위 제공자 또는 다른 서비스 전체 로그아웃까지 보장하는 것은 아니다. 다른 앱도 같은 Auth0 SSO를 사용하면 영향 범위를 테스트한다.
